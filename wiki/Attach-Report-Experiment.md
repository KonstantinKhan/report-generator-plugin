# Эксперимент: сохранение готового отчёта (ветка `experiment/attach-report-to-document`)

## Идея

Сервер Web API не умеет действовать от имени пользователя (`Auth/impersonate` на нашем стенде падает с `Member inIdActor ... is not found in result set`), а запись под админом упирается в блокировки и авторство. Поэтому **в ЛОЦМАН файл пишет плагин, а не сервер**:

1. Плагин отправляет id на сервер, сервер строит PDF (читает данные под служебной учёткой, как раньше).
2. Плагин скачивает PDF с сервера: `GET /reports/{id}`.
3. Пользователь выбирает:
   - **Сохранить на диск…** — стандартный `SaveFileDialog`;
   - **Прикрепить к объекту** — `INetPluginCall.RunMethod("UpFileById", ...)`. Вызов идёт под сессией пользователя клиента: его права, его блокировки, его рабочий проект.
4. **Файлы объекта** — диагностика: `GetInfoAboutVersion` (режим 7), чтобы подсмотреть, какой `Путь файла` используют существующие файлы.

Справка по методам — `raw/AppServer/ЛОЦМАН API.chm` (`UpFileById`, `UpFile`, `RegistrationOfFile`, `GetInfoAboutVersion`).

## Что изменено

- Сервер (`report-generator`, ветка `experiment/report-download`): `GET /reports/{id}` отдаёт PDF (`application/pdf`). `id` — только UUID, иначе 400; нет файла — 404. Покрыто тестами.
- Плагин: `ServerConfig.reportDownloadEndpoint` (по умолчанию `reports/{reportId}`), `LoodsmanFileUploader` (вызовы `RunMethod`), кнопки в `ExternalApiForm`. `INetPluginCall` теперь передаётся из `ExternalApiPluginClass` через `ReportSelectionForm` в `ExternalApiForm`.

## Как проверить на стенде

### 1. Сервер

```
git checkout experiment/report-download      # репозиторий report-generator
./gradlew :report-server:run                 # или docker compose, как обычно
```

Проверка без плагина: `curl -X POST http://<host>:8080/specifications/<versionId>` вернёт `{"id":"<uuid>", ...}`, затем `curl -o r.pdf http://<host>:8080/reports/<uuid>` — должен скачаться валидный PDF.

### 2. Плагин

```
git checkout experiment/attach-report-to-document   # этот репозиторий
dotnet build ExternalApiPlugin/ExternalApiPlugin.csproj -c Debug
```

Скопировать `ExternalApiPlugin.dll`, `Interop.Loodsman.dll`, `server-config.json` (и остальные dll из `bin/Debug`) в `PluginStore`, как в [Build-And-Deploy](Build-And-Deploy.md). `baseUrl` в `server-config.json` — адрес сервера отчётов, достижимый с машины клиента. Перезапустить клиент ЛОЦМАН.

### 3. Сценарии

Выделить объект (лучше тестовый документ) → «Отчеты → Выбрать отчёт» → спецификация. После «Отправить на сервер» должно появиться «Отчёт скачан: N байт», и откроется панель с кнопками.

| # | Сценарий | Что смотреть |
|---|---|---|
| 1 | **Сохранить на диск…** | Файл открывается как PDF. |
| 2 | **Файлы объекта** на объекте, у которого уже есть файл | В логе колонки и значения. Запомнить, что стоит в колонке с путём файла (`_LOCALNAME`/аналог) — это допустимое значение «Путь файла». |
| 3 | **Прикрепить к объекту**, путь пустой, объект **не** взят в работу | Результат: успех или текст ошибки? Если ошибка про checkout/блокировку — для записи нужен рабочий проект. |
| 4 | То же, объект **взят в работу этим пользователем** | Файл должен добавиться (после check-in виден в карточке). |
| 5 | То же, объект **заблокирован другим пользователем** | Должна быть понятная ошибка, не падение клиента. |
| 6 | Повторное «Прикрепить» с тем же именем | Ожидаем обновление содержимого (по документации `UpFileById` обновляет файл с тем же именем). |
| 7 | Путь из сценария 2 вместо пустого | Сравнить с сценарием 3. |

После успешной записи проверить в клиенте: файл виден у документа, автор и дата — этого пользователя, не служебной учётки.

### 4. Что прислать мне

Для каждого сценария — текст из окна плагина целиком. Особенно важно:

- **Как `RunMethod` сообщает об ошибке**: бросает исключение или возвращает код/строку. Сигнатура `UpFileById` в справке с out-параметрами `inReturnCode`/`stErrorMessage`; плагин передаёт только входные (шесть аргументов). Если вызов падает с ошибкой про число или тип аргументов — пришлите текст исключения, поправим порядок/типы.
- Принимает ли `UpFileById` `byte[]` и `DateTime` как есть.
- Нужен ли checkout (сценарий 3 против 4).
- Допустимый «Путь файла» (сценарий 2 и 7).

## Результаты проверки

- Скачивание отчёта с сервера работает (PDF 16 КБ).
- **Сценарий 3** (объект не в работе): `RunMethod("UpFileById", ...)` бросает `COMException 0x8000FFFF: Это действие применимо только в режиме редактирования`. Вывод: вызов и типы аргументов (`int`, `string`, `string`, `byte[]`, `DateTime`, `bool`) принимаются, ошибка приходит исключением, а для записи объект должен быть взят в работу (checkout).

- **Сценарий 4** (автор объекта, объект в рабочем проекте, `PluginCall.CheckOut = 781`): режим редактирования пройден, новая ошибка `400226: Файл может быть связан только с документом`. Выделенный объект (по нему строили отчёт) — не документ. Вывод: нужна навигация к документу-получателю.

## Навигация к документу: пункт меню «Сохранить отчёт в выбранный документ»

1. Сформировать отчёт в окне плагина — он запоминается в памяти плагина (`PendingReport`, живёт до перезапуска клиента).
2. Закрыть окно, свободно перейти в клиенте к нужному документу в рабочем проекте.
3. «Отчеты → Сохранить отчёт в выбранный документ». Пункт **активен только если** есть отчёт и выбранный объект принимает файл. Проверка — `GetInfoAboutVersion` режим 15: `_DOCUMENT` = 1, `_ACCESSLEVEL` ≥ 2, `_LOCKED` = 1 (заблокирован в текущем рабочем проекте), `PluginCall.CheckOut` ≠ 0. Если сама проверка упала или колонки не пришли — пункт остаётся активным (fail-open), причину отказа покажет команда.
4. Команда спрашивает подтверждение с именем документа и вызывает `UpFileById`.

### Плавающая панель «Сохранить / Отмена» (замена неудобного флоу)

Кнопка **«Сохранить в документ…»** в окне отчёта закрывает окна плагина и открывает небольшую немодальную панель справа сверху: статус выделения, **Сохранить** (активна только если выделенный объект принимает файл — те же проверки, что выше) и **Отмена** (закрывает панель и забывает отчёт). Панель привязана владельцем к главному окну клиента (сворачивается вместе с ним). Пункт меню «Сохранить отчёт в выбранный документ» остался как запасной путь.

Выделение панель получает двумя путями: из `enableCheck` пунктов меню (клиент вызывает его при смене выделения) и по таймеру (800 мс) из последнего известного `INetPluginCall`. В серой строке под статусом написано, какой путь сработал последним (`меню` или `таймер`). **Это главное, что надо выяснить на стенде**: документация не говорит, «живой» ли `IPluginCall` или снимок на момент вызова.

| # | Сценарий | Что смотреть |
|---|---|---|
| 13 | «Сохранить в документ…», затем кликать по объектам в дереве | Статус меняется? Источник: `таймер` или `меню`? Если не меняется вообще — выделение не доходит, пришлите, на что кликали. |
| 14 | Встать на документ в рабочем проекте → «Сохранить» | Файл добавлен, панель закрылась. |
| 15 | Встать на не-документ | «Сохранить» неактивна, причина в статусе. |
| 16 | «Отмена» | Панель закрыта, пункт «Сохранить отчёт…» в меню снова неактивен. |
| 17 | Свернуть/развернуть клиент | Панель сворачивается вместе с ним (если нет — владелец не установился). |
| 18 | Мышь по кнопкам панели | Кликается нормально. Риск: немодальное WPF-окно внутри не-WPF процесса; клавиатурный ввод в нём может работать некорректно, мышь — должна. |

### Документ не в рабочем проекте: автоматический checkout

Если выделенный документ свободен (`CheckOut = 0`, `_LOCKED = 0`), панель/команда предлагают **«Взять в работу и сохранить»**. Плагин делает цепочку нативных методов на подключении клиента:

`CheckOut(type, product, version, 0)` → имя рабочего проекта → `ConnectToCheckOut(name, db)` → `UpFileById(...)` → `CheckIn2(name, db)`.

По документации `CheckIn2` возвращает подключение в режим базы данных, так что окно просмотра остаётся в прежнем режиме. При любой ошибке после взятия в работу плагин выполняет `DisconnectCheckOut` и `CancelCheckOut2`, чтобы не оставить блокировку.

Решение по статусу объекта (`GetInfoAboutVersion`, режим 15):

| Состояние | Результат |
|---|---|
| не документ | отказ |
| нет прав на изменение (`_ACCESSLEVEL` < 2) | отказ |
| в рабочем проекте, заблокирован в нём | прямая запись `UpFileById`, сохранение рабочего проекта делает пользователь |
| в просмотре, свободен (`_LOCKED` = 0) | автоматический checkout → запись → check-in |
| в просмотре, заблокирован другим (`_LOCKED` = 2) | отказ |
| в просмотре, уже взят вами в другом проекте (`_LOCKED` = 1) | отказ с подсказкой |

| # | Сценарий | Что смотреть |
|---|---|---|
| 19 | Документ в просмотре, свободный → «Взять в работу и сохранить» | Файл у документа; статус «Документ сохранён в базу»; в списке рабочих проектов ничего не осталось. |
| 20 | После 19 окно просмотра продолжает работать (обновить, перейти по дереву, открыть карточку) | Подключение осталось в режиме базы, ничего не «залипло». Это главный риск. |
| 21 | Документ заблокирован другим пользователем | Панель: «заблокирован другим пользователем», кнопка неактивна. |
| 22 | Нет прав на документ | «нет прав на изменение». |
| 23 | Спровоцировать ошибку записи (например, файл с недопустимым именем в поле/подмена) и проверить уборку | После ошибки объект не остался заблокированным (нет висящего рабочего проекта). |
| 24 | Повторить 19 с тем же именем файла | Файл обновляется (не дублируется). |

Что присылать: текст ошибки целиком и состояние объекта до/после (взят в работу или нет). Особенно важно: вернулся ли клиент в режим базы после `CheckIn2` и создаётся ли при check-in новая версия/ревизия файла.

### Объект заблокирован другим пользователем

Это штатное поведение ЛОЦМАН: пока документ в работе у другого, записать в него файл нельзя (и вторичное представление тоже — `IView.Save` бросает исключение). Обходить это не нужно; снимать чужую блокировку (`UnlockObject`) — только админом и по месту, не из плагина. Что сделано вместо:

- В статусе панели показывается, **кто держит объект и с какого времени** (`GetInfoAboutVersion`, режим 12: `_FULLNAME`, `_NAME`, `_DATE`, `_COMMENTS`).
- На панели есть кнопка **«На диск…»**: отчёт можно сохранить в файл, не закрывая панель. Отчёт остаётся в памяти, потом можно выбрать другой документ.

| # | Сценарий | Что смотреть |
|---|---|---|
| 25 | Встать на документ, заблокированный другим пользователем | «Нельзя сохранить: объект заблокирован другим пользователем. Заблокировал: ФИО (логин), с дд.мм.гггг чч:мм». |
| 26 | «На диск…» в этом состоянии | Файл сохраняется, панель остаётся, можно выбрать другой документ. |
| 27 | Блокировка без комментария / без ФИО | Статус не ломается (показывает то, что пришло). |

## Что не сделано (осознанно)

- Выбор **другого** документа для прикрепления (сейчас — выделенный объект). Кандидат: клиентский диалог `lnSelectObject2` из `IMetodsWorkObject`; до него ещё надо добраться из плагина.
- Автоматический checkout/check-in. Сначала узнаём из сценариев 3–5, нужен ли он.
- Аутентификация скачивания на сервере отчётов: `GET /reports/{id}` отдаёт любой PDF по UUID без проверки. Для эксперимента допустимо, для продакшена — нет.
- Очистка старых PDF на сервере.
- Кодовая сторона `UpFileById` не проверялась против реального `Ascon.Plm.Loodsman.PluginSDK.dll` (на машине разработки его нет): сборка проверена только против заглушки с теми же сигнатурами `RunMethod`/`GetDataTable`, как в [IPluginCall-And-Object-Id](IPluginCall-And-Object-Id.md).
